# Def Jam PS5 reuse audit against SC2

Checkpoint: 2026-11-06. Read-only implementation audit; no runtime/tool edits, builds, console access or Git operations. Forge owns integration. The console remains untouched while the owner tests.

Inspected donor: [elripalda/defjam-ps5](https://github.com/elripalda/defjam-ps5/tree/572bcab1710e5e5273d0fe09e3192c9001fa9be4), commit `572bcab1710e5e5273d0fe09e3192c9001fa9be4`. Local SC2 source was inspected directly; this is source compatibility evidence, not a new PS5 gameplay result.

## Findings that affect decisions

1. **Do not replace SC2's shaderc implementation with Def Jam's subset.** SC2 requires a macro-definition API missing from that implementation. Its requested compiler behavior also differs. This would introduce a known incompatibility without evidence that the current full shaderc compiler is the failing subsystem.
2. **The selected PS5 SDL controller backend already implements most of Def Jam's useful controller behavior.** Replacing it or adding a second direct scePad/virtual-controller stack risks duplicate devices and handle ownership conflicts.
3. **SC2 already handles the touchpad/menu distinction in its actual game override.** `runtime/input_host_win32.c:315–320` aliases TOUCHPAD to BACK only in aggregate menu polling, deliberately not injecting an Xbox guest button. The shared third-party file alone would give the wrong conclusion. No duplicate patch is justified. The lead identified the existing override's introduction commit as `e5c1990`.

## Shader compiler API and format compatibility

Donor files: [ps5/shaderc/shaderc_glslang.cpp](https://github.com/elripalda/defjam-ps5/blob/572bcab1710e5e5273d0fe09e3192c9001fa9be4/ps5/shaderc/shaderc_glslang.cpp) and [ps5/cmake/ps5.cmake](https://github.com/elripalda/defjam-ps5/blob/572bcab1710e5e5273d0fe09e3192c9001fa9be4/ps5/cmake/ps5.cmake).

| Area | Actual SC2 contract | Def Jam comparison / consequence |
| --- | --- | --- |
| Link/API | `runtime/d3d_shader_compiler.cpp:76–90` binds the actual linked shaderc C API. Compiler/options/results remain opaque. | Similar C API subset, not a complete shaderc replacement. |
| Macros | `compileSpirv:179–188` calls `shaderc_compile_options_add_macro_definition` for `RECOMP_UNIFORM_SET` (vertex `1`, fragment `3`), default/sample-specific `RECOMP_SAMPLE_COUNT`, and every dynamic define. | **Missing macro-definition function.** Required functionality must be implemented and tested first. |
| Language/stage | SC2 supports HLSL and preprocessed GLSL presets, vertex and fragment stages. | Handles GLSL/HLSL and vertex/fragment. |
| Entry point | SC2 passes the requested entry name; preset path uses `main`; cached SPIR-V must contain the matching execution model/name. | Sets both source/output entry points. |
| Constant layout | SC2 enables HLSL offsets and auto-mapped locations. Its current uniform policy assumes float4/float4x4 compatibility. | Provides HLSL-offset and location controls. |
| Resource bindings | SC2's generated shader sources and presenter use explicit sets/bindings, including `RECOMP_UNIFORM_SET`. These must match SDL GPU resource counts and layout. | Offers binding shifts and HLSL I/O mapping; equivalence is unproven. |
| Optimization | HLSL requests performance optimization; GLSL requests none so reflection names survive. | Ignores optimization level; disables optimizer. |
| SPIR-V | SC2 profiles requests/cache keys and validates bounded SPIR-V size, alignment, magic, instruction bounds and matching OpEntryPoint. | Emits Vulkan 1.0/SPIR-V 1.0; validator disabled. |
| Includes | `third_party/doa2u-re/recomp-runtime/d3d_shader_chain.cpp:129–161` inlines `.slang` includes before compiling, with a nesting/error path. No include-callback API is bound by SC2. | No includer supplied. Keep SC2 preprocessing. |

The critical SC2 request identity is implemented in `runtime/sc2_shader_provision.h`, not in shaderc alone. `ShaderMakeRequest` serializes stage, language, entry point, defines and source into the request identity. Provisioned binaries are read before native compilation. Fresh native results are checked by `ShaderSpirvValid` and stored under that policy. A compiler replacement must preserve that behavior and bump the profile/cache identity if output policy changes; returning any syntactically plausible SPIR-V is insufficient.

`runtime/sc2_presenter_shaders.h:6–8` demonstrates explicit descriptor set `2` for textures/samplers and macro-selected uniform set. Additional material shaders are generated by `third_party/doa2u-re/recomp-runtime/d3d_draw_shader.cpp`. A replacement that omits the macro preamble can fail compilation or compile a different layout. Descriptor reflection/binding compatibility must be compared on representative fixed, dynamic material and preset shaders before considering a swap.

**Safe current reuse:** the idea of a smaller compiler facade and its explicit environment/entry handling can inform a future size/startup-cost optimization. Actual replacement is blocked by the missing macro API and absence of a measured SC2 deficiency. Keep the existing full static shaderc build now. No performance benefit is asserted.

## DualSense data path and semantics

Donor: [ps5/src/host_ps5.c](https://github.com/elripalda/defjam-ps5/blob/572bcab1710e5e5273d0fe09e3192c9001fa9be4/ps5/src/host_ps5.c), especially lines 92–158 and the virtual joystick setup.

Actual SC2 selected backend source:

`C:/.pe/ps5-native/gpu-platform-20261030/attempt-resolution-mods-20261031/sdl3-src/src/joystick/ps5/SDL_ps5joystick.c`

That is read-only reference source for the selected SDL archive, not a file modified by this task. It includes its Zlib notice and identifies its altered public-source origin. Game-facing SC2 code is the override `runtime/input_host_win32.c`, which supersedes `third_party/doa2u-re/recomp-runtime/input_host_win32.c` in the merged-source build. It uses SDL outside Windows despite its historical filename. `runtime/sc2_input.cpp` applies configurable bindings, and `runtime/sc2_menu.cpp` handles the host menu. The actual `input_host_win32.object.json` source SHA256 matches the override (`0b8483846140133e05941091d53fbad846a76406e13274e8ae9a7d7b0b283df1`) and its dependency origin names that file; this proves which implementation is compiled.

| Behavior | SC2 + selected SDL source evidence | Donor lesson and reuse decision |
| --- | --- | --- |
| Device architecture | SDL has its own native PS5 joystick driver, user-ID matching, handle ownership and up-to-four-user detection. SC2 opens SDL gamepads into guest ports. | Def Jam supplies virtual SDL gamepads from scePad. Do not run both stacks. |
| Face buttons | SDL maps Cross/Circle/Square/Triangle to A/B/X/Y positions. SC2 maps south/east/west/north to Xbox A/B/X/Y. | Same positional convention; no replacement needed. |
| Triggers | SDL native joystick publishes `raw*257-32768`; SDL gamepad normalizes to 0…32767; SC2 converts to 0…255 with `>>7`. | Donor explicitly warns that virtual joystick trigger input must use the full signed range. Existing selected SDL already does. |
| Sticks | Native PS5 driver centers raw 127/128 and scales both sides; SC2's `up_axis` converts SDL down-positive Y to Xbox up-positive. | Preserve the existing two-stage convention. No observed deadzone/gameplay defect yet. |
| Read failure/disconnect | Native SDL forces recentering on scePad read failure and zeros disconnected pad state. SC2 drops disconnected SDL handles. | Donor also releases controls on failure; current behavior already covers the important stuck-input case. |
| Rumble | SC2 calls `SDL_RumbleGamepad` with 16-bit motors and a one-second renewed duration; SDL sends upper eight bits through scePad and returns actual errors. | Donor has its own virtual-device callback. Prefer the already-selected native route. |
| Touchpad/back | SDL backend maps touchpad to TOUCHPAD, while the **actual SC2 override** aliases TOUCHPAD→BACK in aggregate polling at lines315–320. Menu `OpenHeld` checks that aggregate BACK bit. Guest button sampling is deliberately unchanged. | Donor maps physical touchpad to SDL BACK globally. SC2 already has a narrower separation; retain it. Do not implement a duplicate alias or infer an input failure from shared source. |
| Advanced effects | Native SDL returns unsupported for trigger rumble, effects and sensors. | Do not market motor rumble as adaptive-trigger/haptic/sensor support. No such upgrade was implemented. |

The existing touchpad adaptation distinguishes host menu access from guest Xbox Back binding. Its regression acceptance should remain: touchpad opens/closes the host menu as designed, Options remains guest Start, remapped Back remains usable, both player assignments survive disconnect/reconnect, and trigger-neutral values remain zero at the Xbox boundary. These are later human input checks, not evidence of a missing implementation or a GPU-startup cure. The override also retries failed SDL gamepad initialization after one second rather than permanently marking it initialized.

Its bundled MihawkGen code has separate GPL terms; it is not part of this recommendation. glslang, Vulkan headers, SDL and any newly linked libraries retain their own notices. Conceptual lessons require less integration risk than wholesale modules: explicit Vulkan availability errors, host-controller failure release behavior and compiler environment declarations. The Vulkan wrapper generator's unresolved-pointer hazard is documented in `research/ARCHITECTURE-COMPARISON.md`; do not import it to solve a null-call crash.

## Next justified action

Wait for the actual installed RADV-dispatch candidate's result and independent code/error review. Keep shader and input replacements out of the boot-fix batch unless the earliest failing operation points there. If the game reaches input, validate its **existing** menu alias, triggers, player assignment and rumble before changing them. No missing touchpad implementation was found after resolving the actual override. If shader compilation fails, capture the exact source/defines/stage/entry request and error, then compare it against the full shaderc implementation before considering the donor subset.
