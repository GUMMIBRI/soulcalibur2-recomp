## Decision for the current boot milestone

**Continue the Xbox foundation, selectively reuse verified PS5 platform solutions, and do not migrate to HD Online now.** This is an engineering recommendation, not migration authorization. The current observed failure has been narrowed to host graphics initialization, including a confirmed weak RADV archive extraction defect. Changing guest architecture would replace working extraction, three-exclusive conversion, Xbox runtime and save integration while still requiring a PS5 Vulkan/platform solution. A new guest CPU does not remove a bad host driver link.

The latest locally recorded installed candidate at research start is RADV-dispatch-r1, source `c4195d4`, eboot 57,397,305 bytes, SHA256 `cf7a5063e9c7db741c453dc5d1c55e958197998184a09cb755d5053199792c95`. Its result must be read from a fresh owner test/log; do not reinterpret the prior `78bec2f9…` crash as a result for this candidate. Authoritative local receipt: `private/native-xbe-retest/RADV-DISPATCH-UPLOAD.json`. No claim of interactive PS5 gameplay follows from compilation or the architecture survey.

## What the implementations actually offer

### Current Xbox project: highest compatibility

The public [runtime documentation](https://github.com/tmcleroy/soulcalibur2-recomp/blob/8a914a85efe929b3a43f74265ccdd5b4583940be/docs/runtime.md), `runtime/runner.cpp`, `runtime/sc2_guest.cpp`, `guest/vmp.cpp`, `guest/vmx.cpp` and `runtime/sc2_netplay.cpp` are the directly related implementation family. Our checkout already contains PS5 overrides and authenticated generated-code receipts. Local submodule pins at review: doa2u-re `8464693079a9feb32ab38136a224caf9163d6b71`; xboxrecomp `653782777dee86b70030622a64efb53d6d06cc0b`.

Directly useful: upstream fixes to the same adapters, shader generation, guest model conversion, save contract and rollback model, individually diffed against our pins. Do not reset submodules or update the whole runtime during boot debugging. New host syscall assumptions can regress a PS5 build. GPL-3.0-or-later and per-dependency notices apply.

### HD Online: a distinct port, not a renderer upgrade package

[docs/architecture.md](https://github.com/n0madic/Soulcalibur2HD-recomp/blob/3e96e66aebdf33671e9f6a44fd0c77f0d7b95f07/docs/architecture.md) and [src/CMakeLists.txt](https://github.com/n0madic/Soulcalibur2HD-recomp/blob/3e96e66aebdf33671e9f6a44fd0c77f0d7b95f07/src/CMakeLists.txt) implement a host plus owner-generated PPU/SPU module. Runtime exports, function-table lookup, TLS accessor functions and a header/lifter ABI hash bind the two. An optional monolithic link exists, so desktop `dlopen` is not an insurmountable architectural requirement.

A PS5 port would nevertheless require PS3 HLE/SPURS/SPU scheduling, RSX shader/draw translation, memory/endian behavior, audio/media support and a PS5-specific backend. The Linux Vulkan path uses SDL2 and a dynamically loaded desktop Vulkan library, with X11/Wayland assumptions. Its Metal path does not map to PS5. Useful design reference: ABI identity checks and keeping generated modules private. It is not a compatible Xbox XBE loader, D3D8 adapter or SC2 guest-OLK converter. [Licensing](https://github.com/n0madic/Soulcalibur2HD-recomp/blob/3e96e66aebdf33671e9f6a44fd0c77f0d7b95f07/docs/licensing.md): inspect GPL-2-or-later project terms and Apache dependencies together; the distributed combination is GPL-3-or-later.

### Ring Out and Voldorium: useful evidence, high transplant cost

Ring Out's [ModernGekko/PROVENANCE.md](https://github.com/jackpoison-prog/RingOut/blob/9339899231d9cf90282c7b4c17eb1cf0c3c4e14c/ModernGekko/PROVENANCE.md) explicitly identifies Dolphin provenance and separately licensed components. Its `ModernGekko/src/gpu/{gx_command_processor,gx_pipeline,gx_texture_decoder}.cpp` and `src/runtime/dolphin_runtime.cpp` process GX state, not NV2A/D3D8. A switch means porting that hardware/runtime stack. Per-file licenses matter: ModernGekko states GPL-3-or-later, while other components carry their own terms. No emulator-derived changes should be submitted upstream under the user's standing rule.

Voldorium's [port/m1/build.sh](https://github.com/enrique363/voldorium/blob/f02cfc9e448757670695f011362b3ed2c3d8b191/port/m1/build.sh) builds SDL2/OpenGL/pthread code, with separate `render.c`, `ta.c`, `aica.c`, `arm7.c`, `state.c` and `netplay.c`. Its [port/README.md](https://github.com/enrique363/voldorium/blob/f02cfc9e448757670695f011362b3ed2c3d8b191/port/README.md) describes register/memory differential tests that exposed aliasing and FP-mode bugs: a useful validation pattern. SH-4 timing, VMU data and PowerVR packets cannot replace the Xbox equivalents. The top-level license gap blocks direct reuse even where ideas are useful.

## Xbox 360 PS5 evidence is useful, but different

[bystritskiy/speedbreaker-ps5](https://github.com/bystritskiy/speedbreaker-ps5/tree/2633d793d9fb2971cfe0528e08a25bc19198aba3), `2633d793d9fb2971cfe0528e08a25bc19198aba3`, is an actual public XenonRecomp/Xenos-to-PS5 project, not evidence that Xbox x86 and Xbox 360 PPC runtimes are interchangeable. Its [port/ps5/sdl/SDL_ps5vulkan.c](https://github.com/bystritskiy/speedbreaker-ps5/blob/2633d793d9fb2971cfe0528e08a25bc19198aba3/port/ps5/sdl/SDL_ps5vulkan.c) seeds the static ICD and enumerates real physical devices, displays, modes and planes for VK_KHR_display. It checks actual results instead of assuming a desktop window system. The surrounding code uses public LLVM/payload SDK/RADV and has detailed third-party notices.

Reusable platform concepts: static driver linkage, complete Vulkan dispatch, display/AudioOut/input adapters, application imports and diagnostics. Not interchangeable: XEX loader, PPC context, XAM, XMA audio and Xenos shader translator. A PS5-compatible Vulkan backend still needs validation against the exact RADV build and guest renderer's requirements.

2. If the GPU still fails, compare exact function availability and WSI/device capability handling with the pinned PS5 references above. Do not work around journal checks or change guest architecture to hide host failures.

4. Architectural reconsideration requires a finite prototype showing a specific current blocker is removed, with equivalent asset, controller and rendering evidence. Compiler success alone is insufficient.
